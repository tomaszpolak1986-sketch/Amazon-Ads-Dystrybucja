Instrukcja dla administratora konta

Dostęp SP-API dla AdsPanel

Druga, osobna integracja — obok tej, którą już nadaliście do Amazon Ads. Ta służy wyłącznie do pobrania raportu sprzedaży, żeby dało się policzyć TACOS. Wymaga uprawnień właściciela konta, dlatego trafia do Ciebie, a nie do użytkownika subkonta.

Dlaczego to osobna sprawa

Amazon Ads API, który już mamy, zna wyłącznie sprzedaż przypisaną do reklam. Sprzedaży organicznej nie zna wcale — sprawdziliśmy wszystkie kolumny wszystkich raportów. Bez niej nie da się policzyć TACOS, czyli stosunku wydatków na reklamę do całego przychodu.

Tę brakującą część daje Selling Partner API. To odrębne API, z odrębną rejestracją i odrębnymi kluczami — istniejącej aplikacji reklamowej nie da się do tego użyć.

Potrzebna jest jedna rola: Brand Analytics. Nie prosimy o żadne dane osobowe klientów ani o role ograniczone (PII). To istotnie skraca procedurę — odpada ankieta bezpieczeństwa i cała ścieżka wokół danych wrażliwych.

Co trzeba zrobić

  1. Otwórz rejestrację dewelopera

    W Seller Central, na koncie głównym:

    Apps and Services → Develop Apps

    Jeśli konto zostało już przeniesione do Solution Provider Portal, ta sama strona jest dostępna stamtąd.

  2. Wypełnij profil dewelopera

    W sekcji Data Access wybierz opcję dla integracji własnej firmy:

    Private Developer: I build application(s) that integrate my own company with Amazon Services APIs

    W sekcji Roles zaznacz wyłącznie:

    Brand Analytics

    Nie zaznaczaj ról oznaczonych jako restricted ani niczego związanego z danymi kupujących — nie są nam potrzebne, a wydłużają weryfikację.

  3. Wklej opis zastosowania i zabezpieczeń

    Formularz pyta o Use Cases i Security Controls. Amazon to czyta i potrafi dopytać, więc poniżej gotowe teksty opisujące stan faktyczny. Formularz jest po angielsku.

    Use case — do wklejenia

    Internal tool used solely by our own organization to manage our own Amazon Advertising campaigns. The application retrieves the Sales and Traffic report (GET_SALES_AND_TRAFFIC_REPORT) via the Reports API in order to calculate TACOS (Total Advertising Cost of Sale), which compares advertising spend against total revenue including organic sales.

    The data is aggregated sales and traffic per day and per ASIN. It is used only for internal advertising decisions, is not resold, not shared with any third party, and not used for any purpose other than reporting inside our own company. No personally identifiable information is requested, retrieved, stored or processed.

    Security controls — do wklejenia

    Data is stored on a dedicated server under our own control (Debian Linux, Docker). The PostgreSQL database is bound to localhost only and is not reachable from the internet. The application is served over HTTPS and protected by password authentication; only named employees of our company have access.

    API credentials and refresh tokens are stored in a configuration file with 0600 file permissions, outside of version control, and are never written to logs or transmitted in URLs. Access is read-only: the application only downloads reports and performs no write operations through SP-API. Encrypted daily backups of the database are retained on the same server.

  4. Wyślij i pilnuj skrzynki

    Po kliknięciu Register Amazon zakłada sprawę i odpisuje na adres administratora konta.

    Pięć dni na odpowiedź. Jeśli Amazon poprosi o dodatkowe wyjaśnienia, a odpowiedź nie przyjdzie w ciągu pięciu dni, sprawa zostaje zamknięta i trzeba zaczynać od nowa. Warto sprawdzać skrzynkę, także folder ze spamem.

  5. Utwórz aplikację prywatną

    Po zatwierdzeniu profilu, na tej samej stronie Develop Apps, dodaj nową aplikację typu SP-API. Po utworzeniu aplikacja ma własne LWA credentials — client ID i client secret.

  6. Autoryzuj ją na własnym koncie

    Przy aplikacji na liście kliknij Authorize app. Amazon wygeneruje refresh token i pokaże go na ekranie.

    Token pokazuje się raz. Skopiuj go od razu. Gdyby przepadł, nic złego się nie stanie — wystarczy kliknąć Authorize app ponownie, a poprzednie tokeny pozostają ważne.

Do odesłania

Trzy wartości — ten sam komplet co przy dostępie do Ads API:

LWA client IDzaczyna się od amzn1.application-oa2-client.
LWA client secretzaczyna się od amzn1.oa2-cs.v1.
refresh tokenzaczyna się od Atzr|
Nie mailem i nie komunikatorem. Te trzy wartości dają pełny dostęp do raportów konta. Najlepiej przekazać je osobiście albo menedżerem haseł. Gdyby kiedykolwiek wyciekły, autoryzację można cofnąć w tym samym miejscu, w którym się ją nadaje.

Czego nie trzeba robić

RzeczDlaczego odpada
konto AWS Amazon zniósł ten wymóg w październiku 2023.
rola IAM Nie jest już potrzebna do żadnego wywołania SP-API.
podpisy SigV4 Wystarczy zwykły token LWA, tak jak w Ads API.
publikacja aplikacji Aplikacja prywatna działa tylko na własnym koncie, nie trafia do katalogu.
role PII Nie pobieramy danych kupujących, więc nie prosimy o te uprawnienia.

Co to oznacza dla konta

  • Tylko odczyt. Integracja pobiera raporty i nic nie zapisuje przez SP-API.
  • Jeden raport. Sales and Traffic — dzienna sprzedaż i ruch, zbiorczo oraz per ASIN.
  • Bez danych osobowych. Nie prosimy o nazwiska, adresy ani dane zamówień kupujących.
  • Odwracalne. Autoryzację można wycofać w każdej chwili w Seller Central.
  • Niezależne od Ads API. Cofnięcie jednego nie rusza drugiego.
