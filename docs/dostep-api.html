Instrukcja dla administratora konta

Dostęp API dla AdsPanel

Budujemy wewnętrzne narzędzie do zarządzania naszymi kampaniami Sponsored Products. Żeby je podłączyć, potrzebne są trzy rzeczy z Twojej strony. Wszystkie w konsolach, do których masz dostęp jako administrator.

Czas: ok. 10 minut Nowy wniosek do Amazona: niepotrzebny Etykiety niemieckie podane w nawiasach
Konto, którego dotyczy
amzn1.ads-account.g.XXXXXXXX

Co trzeba zrobić

  1. Przesłać Client ID i Client Secret z istniejącego Security Profile.
  2. Dopisać jeden adres zwrotny na liście dozwolonych adresów.
  3. Sprawdzić rolę użytkownika, który będzie korzystał z narzędzia.

Dostęp do Ads API na koncie już istnieje — w konsoli reklamowej widać autoryzowane aplikacje. Korzystamy z tego, co jest, więc nie ma potrzeby składania nowego wniosku ani czekania na akceptację Amazona.

1

Client ID i Client Secret

ok. 5 min · konsola deweloperska

To dane identyfikujące aplikację, nie osobę. Znajdują się w Security Profile, który został utworzony przy uzyskiwaniu dostępu do Ads API dla konta wskazanego powyżej.

developer.amazon.com→Login with Amazon→wybierz Security Profile→ikona koła zębatego→Web Settings
  • Client ID — długi ciąg zaczynający się od amzn1.application-oa2-client.
  • Client Secret — ukryty, pokazuje się po kliknięciu Show Secret

Obie wartości prześlij bezpiecznym kanałem — najlepiej menedżerem haseł albo wiadomością, którą da się później usunąć.

2

Adres zwrotny

ok. 1 min · ten sam ekran co w kroku 1

Bez tego wpisu logowanie do narzędzia nie zadziała — Amazon odrzuci przekierowanie po zalogowaniu. W tej samej zakładce Web Settings jest pole Allowed Return URLs. Dodaj tam:

http://localhost:9090/redirect
Musi być dokładnie taki ciąg. Bez ukośnika na końcu, z http — nie https — i z portem 9090. Każda różnica, nawet jeden znak, powoduje błąd redirect_uri mismatch i logowanie się nie powiedzie.

Adres wskazuje na komputer lokalny, więc nie otwiera niczego na zewnątrz. Służy wyłącznie do jednorazowego przekazania kodu autoryzacyjnego z przeglądarki do narzędzia.

3

Rola użytkownika

ok. 3 min · konsola reklamowa

Narzędzie działa z uprawnieniami tej osoby, która się w nim zaloguje — ani mniej, ani więcej. Dlatego warto sprawdzić, co ma przypisane konto, które będzie z niego korzystać.

advertising.amazon.com→ustawienia konta (Kontoeinstellungen)→zarządzanie użytkownikami→kolumna Rolle

Dwie rzeczy do potwierdzenia:

  • Rola z prawem edycji. Rola tylko do odczytu wystarczy do raportów i analiz, ale każda próba zmiany stawki, budżetu czy dodania wykluczenia zwróci błąd uprawnień. Nazwy ról różnią się między kontami — chodzi o poziom pozwalający edytować kampanie.
  • Dostęp do wszystkich trzech rynków — DE, ES oraz IT. Narzędzie zobaczy wyłącznie te profile, do których użytkownik ma dostęp. Jeśli brakuje któregoś, ten rynek po prostu nie pojawi się w panelu.

Czego nie trzeba robić

Nie udostępniaj hasła ani nie loguj się za kogoś. Każdy loguje się sam, swoim kontem.
Nie składaj nowego wniosku o dostęp do Ads API. Konto już go ma.
Nie odłączaj istniejących aplikacji w sekcji „Autorisierung verwalten”. Jeśli któreś z podłączonych narzędzi realnie zarządza kampaniami, odcięcie go zatrzyma jego automatyzacje.
Nie twórz nowego Security Profile. Korzystamy z tego, który już jest zatwierdzony.

Co to oznacza dla konta

Client Secret identyfikuje aplikację, nie osobę — w obrębie jednej firmy dzielenie go między użytkowników wewnętrznego narzędzia jest normalne. Osobistym poświadczeniem jest token odświeżający, który powstaje dopiero przy logowaniu i zostaje na komputerze użytkownika.

Narzędzie nie wprowadza żadnych zmian samodzielnie. Każda modyfikacja — stawki, budżetu, wykluczenia, statusu kampanii — jest najpierw wyliczana jako propozycja i czeka na ręczne zatwierdzenie w panelu. Dotyczy to również reguł automatyzacji: reguła przygotowuje sugestię, nigdy jej nie wykonuje. Każda zatwierdzona zmiana trafia do dziennika ze starą i nową wartością.

Dostęp można w każdej chwili cofnąć — wystarczy odebrać uprawnienia użytkownikowi w konsoli reklamowej albo usunąć adres zwrotny z Security Profile.
